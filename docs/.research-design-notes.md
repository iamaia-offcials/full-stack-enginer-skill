## Three baseline reasoning probes (before this reviewer's edits)

1. **Existing dense back-office screen, Inter and established brand tokens.** Current DS-001/004/006/008/009, FE-003/006/007 already imply retaining authoritative styles, task hierarchy, shared controls, responsive density and all relevant states. Existing guidance does NOT force a display typeface, marketing hero, sparse card layout or extra motion. Result: baseline succeeds at direction/scope; missing implementation depth is coordinated density (row pitch + padding + type), data typography, optical alignment and review ordering. T app-screen/I operate distinctions help explain why familiarity can be good here, but hard numbers and bans should not become universal.
2. **New editorial site with provided brand.** DS-001/004/006 + UXR-001–010 already prioritize brand, truthful content, actual operations, question-led section order, selective reference comparisons and honest evidence. Result: no need to fix nonexistent generic-template mandate. New useful depth: concise subject-specific direction hypothesis; image/crop/asset evidence; typography as a system; rendered review of hierarchy and composition. Existing brand wins over anti-purple/no-serif/no-gradient house rules. A landing page, article reader and private dashboard can belong to one product while needing different density and emphasis.
3. **Form/table, long supported translations, browser autofill.** FE-006/007, A11Y-003/005, I18N-002/004 already mandate labels/errors, supported RTL/long content, zoom and locale numbers; PRACTICAL-FORMULAS already demonstrates `autocomplete=email`; WEB-004 already supports direct links/history/reload. Result: general requirements exist. Missing concrete depth: cross-field autocomplete/password-manager/paste behavior; preserve values after failed submit and link a multi-error summary; long-token reflow/shrinkable flex/grid; expose essential truncated values; distinguish view state from secret/transient URL state; overlay clipping/focus/scroll restoration. Do not report all autofill, history or localization as wholly absent.

## Stronger existing rules / deliberate rejections

- **Keep local WCAG/platform boundaries.** A11Y-001/006 and DS-005 correctly distinguish normal/large/non-text contrast, exceptions and CSS px vs iOS pt/Android dp. U's main quick-reference still says 44px 'to meet requirements', 4.5:1 for all feedback and point/dp rules in mixed scope; T app border colors can be insufficient if the border is needed to identify a control. Measure actual role/pair. Do not import stricter appearance or target recommendations as AA mandates.
- **Keep local task/operation-led page structure.** U `ui-reasoning.csv` samples use SaaS=glass, micro SaaS=motion/video, e-commerce=urgency; such rules are weak priors, not reliable business truth or conversion evidence. Local UXR-001/002/006 is stronger. Never add scarcity, credentials, testimonials, menus/rates/availability or booking routes just to fill a template. T allows plausible sample room/dish details disclosed only in final report; local runtime-facing truth labeling is stronger.
- **Keep DS-004/009 contextual style and existing foundations.** A's anti-defaults are explicitly context-sensitive; T and I craft-floor include absolute eyebrow/gradient/mono/purple/panel bans. Neither banning Inter nor replacing it by a named 'premium' face improves a dense tool automatically. T explicitly admits violet and several ornaments are owner's preferences, some contradict its own high-scored sample. Do not universalize color/radius/font/count/line/margin rules, no-nested-card rules, minimum image count, or two-line heading cap across locales.
- **Keep motion decisions including none.** T's eight-moving-element gate, required motion layer/two–three scroll scenes and moving picture conflict with the local no-motion candidate, accessibility/performance and frequent-task context. U's maximum 1–2 animations and transform/opacity-only are also overbroad. I craft-floor now allows material effects when measured; local MOT contextual selection is stronger. No motion is valid. Relevant gesture interruption and reduced-motion insights go to existing MOT owner, not a second motion policy.
- **Reject raw upstream automation as authority.** Do not install launchers, hooks, style dealers, bundled binaries, runtime downloads or output their internal command suggestions. No need for random aesthetic seeds, compulsory parallel reviewers, DESIGN.md replacement or snapshot databases to improve this suite. Preserve one source of truth and task-sized retrieval.
- **Correct W's overbroad shortcuts.** Native buttons already provide keyboard behavior; do not add redundant key handlers to every interactive element. aria-label is one naming option, not mandatory when a clear accessible name already exists. A live region is chosen by urgency/semantics, not every async render. URL sync excludes secrets/transient state. Virtualization at >50 items is not a universal threshold and can hurt find-in-page/accessibility; measure. Preload/preconnect only useful assets/hosts. Avoid hiding overflow as the default fix. `type=number` is for actual numeric quantities, not card/phone/postcode identifiers. Title Case, curly punctuation, placeholder ellipses and ampersands are editorial choices, not correctness. Keep platform gesture/scroll expectations.
- **Reject outdated/performance folklore as requirements.** U UX25 still offers fastclick for a 300ms tap delay; do not introduce that dependency by default. Its 16ms-per-frame budget is a 60Hz example, not all devices. Skeletons, spinners, shimmer and optimistic UI are chosen per operation, not mandatory everywhere; no invented progress/time estimates. Neither automatic dark mode nor every-screen icon labels/breadcrumb counts follow merely from broad categories.

## Evidence and scope limits

T's 247-gallery study is a dated selected sample, with model reviewers, limited still captures and explicit fashion bias; the 23-app sample has no phone screens/loading/error states. These are source-reported observations, not independently reproduced evidence or causation. The source labels phone/loading/error rules as house policy. Its detector's pass threshold does not equal AA. I audit's 0–4 scores and T Awwwards-weighted scores are custom rubrics, not certified compliance or user research. Do not import outcome statistics into normative claims.

Most valuable delivery is a short new design-decision/verification guide referenced selectively from existing skills, plus a handful of concrete FE/DS/A11Y/WEB hooks. Avoid replicating entire upstream catalogs, parallel standards or a permanent full research transcript in runtime context. The original practical rule prose above is ready to adapt; optional examples and evidence belong outside the always-loaded SKILL.md.
