## Useful missing implementation knowledge

1. **Initialization and transform ownership.** Import/register only plugins actually used, before setup, using installed-version APIs. Distinguish `to`, `from`, and `fromTo`; later overlapping `from` setups may need `immediateRender: false`. Keep CSS/React/other animation systems from competing for the same transform. Store animation references when playback/interruption is needed. Source: [core skill](https://github.com/greensock/gsap-skills/blob/aed9cfd3277740755f6bfc1155c7aa645403b760/skills/gsap-core/SKILL.md). Placement: optional guide foundations, not a global import recipe.

2. **Timeline ownership.** Use labels/position parameters and local defaults for meaningful sequences; avoid accumulated manual delays. Attach a controlling ScrollTrigger to the parent sequence rather than giving parent-controlled children conflicting playheads. Tween durations determine relative allocation within a scrubbed sequence; changing a whole scrubbed animation's duration does not extend its scroll range. Source: [timeline skill](https://github.com/greensock/gsap-skills/blob/aed9cfd3277740755f6bfc1155c7aa645403b760/skills/gsap-timeline/SKILL.md), [official timeline reference](https://gsap.com/docs/v3/GSAP/Timeline/), [official ScrollTrigger mistakes](https://gsap.com/resources/st-mistakes/). Placement: timeline subsection.

3. **Refresh geometry versus tween measurements.** Function-valued start/end expressions remeasure trigger geometry on refresh. Geometry-derived tween destinations also need function values plus `invalidateOnRefresh: true`; refresh is not magic recomputation of hard-coded JS values. Source: [official ScrollTrigger mistakes](https://gsap.com/resources/st-mistakes/). This distinction is materially absent from the vendor skill. Placement: responsive/dynamic layout subsection.

4. **Refresh timing.** Refresh after committed layout changes from fonts, images or inserted content; coalesce relevant updates, avoid per-frame refresh loops, and avoid triggering stale refreshes after unmount. `refresh()` recomputes start/end; `update()` checks scroll and advances callbacks/animations. Native resize refresh already exists. Source: [official refresh reference](https://gsap.com/docs/v3/Plugins/ScrollTrigger/static.refresh()/). Placement: dynamic layout subsection. Reserving image dimensions and avoiding unbounded observers are applications of current FE/PERF rules, not claims that GSAP solves layout stability.

5. **Pin geometry.** Pin a stable wrapper and animate descendants; account for document flow and flex/absolute layouts before disabling spacing. Pinning can use fixed positioning or transforms. Prefer page-order creation; when priority is necessary, higher values refresh earlier. Source: [official ScrollTrigger reference](https://gsap.com/docs/v3/Plugins/ScrollTrigger/). Placement: pin subsection, with explicit flow verification.

6. **Transformed horizontal containers.** Keep native scrolling the ordinary path. If a justified pinned horizontal presentation is implemented, measure actual overflow in consistent units, keep its parent animation linear, and use `containerAnimation` for descendant triggers. Its descendant triggers cannot pin or snap. Transformed ancestors and `will-change: transform` can affect fixed descendants. Source: [official ScrollTrigger reference](https://gsap.com/docs/v3/Plugins/ScrollTrigger/). Placement: advanced optional subsection, not a default landing-page pattern.

7. **Local lifecycle cleanup.** In React, scope `useGSAP`/context to the owner; use `dependencies` plus `revertOnUpdate` when replacement setup is needed; restrict DOM work to client lifecycle. Context-safe handlers record later-created GSAP resources and preserve scope, but external listeners, timers, requests and stale callback guards remain the owner's responsibility. Revert local ownership on route teardown instead of killing every trigger in the application. Source: [official React guidance](https://gsap.com/resources/React/), [React skill](https://github.com/greensock/gsap-skills/blob/aed9cfd3277740755f6bfc1155c7aa645403b760/skills/gsap-react/SKILL.md). Placement: lifecycle subsection; FE-008 and MOT-014 remain canonical.

8. **Responsive/reduced-motion rebuild.** `gsap.matchMedia()` supplies a context and reverts matching setups as conditions change; release the owner on disposal. Prefer omitting parallax, pins and scroll choreography while leaving final content/controls usable, rather than merely setting duration to zero. Source: [official matchMedia reference](https://gsap.com/docs/v3/GSAP/gsap.matchMedia()/); final-state/access requirement comes from MOT-006/MOT-021. Placement: lifecycle/access subsection.

9. **Text splitting without losing meaning.** Split only units actually animated; wait for fonts or use the installed version's `autoSplit`/`onSplit`, returning the new animation for re-split cleanup/time synchronization. Default ARIA handling can obscure nested links/semantics; avoid splitting interactive text or carefully verify an accessible equivalent without duplicate focus targets. Restore original markup on teardown. Current `onSplit` features date from 3.13+, so do not assume them for an old installed runtime. Source: [official SplitText reference](https://gsap.com/docs/v3/Plugins/SplitText/). Placement: optional text subsection, tied to MOT-005/MOT-017.

10. **SVG task distinction.** Drawing a visible stroke, morphing geometry, and moving an element along a path are separate requirements. DrawSVG operates on stroke, not fill; MotionPath needs coordinate/alignment care; MorphSVG may require converting primitives and checking path mapping. Do not add every plugin. Source: [plugin skill](https://github.com/greensock/gsap-skills/blob/aed9cfd3277740755f6bfc1155c7aa645403b760/skills/gsap-plugins/SKILL.md), [DrawSVG reference](https://gsap.com/docs/v3/Plugins/DrawSVGPlugin/), [MotionPath reference](https://gsap.com/docs/v3/Plugins/MotionPathPlugin/). Placement: concise optional SVG decision table.

11. **High-frequency work.** `quickTo` can reuse a tween for repeatedly targeted pointer values; it does not supply listener cleanup, reduced motion or performance evidence. Source: [performance skill](https://github.com/greensock/gsap-skills/blob/aed9cfd3277740755f6bfc1155c7aa645403b760/skills/gsap-performance/SKILL.md). Placement: performance notes under existing PERF/OPT rules.

12. **FOUC and progressive content.** Immediate `from` rendering happens only after JavaScript executes; it cannot alone prevent an earlier visible frame. Official FOUC guidance uses initial hiding plus a noscript recovery. For this suite, keep essential content visible as the baseline and ensure module/load/setup failure also cannot strand hidden content; noscript alone does not recover a JS-enabled module failure. Source: [official FOUC guidance](https://gsap.com/resources/fouc/); stronger failure requirement derives from MOT-017/MOT-021. Placement: initialization/fallback subsection.

13. **Native versus custom scroll.** ScrollTrigger does not require a smooth-scroll library. Use `scroller` for a native scroll element; use `scrollerProxy` only when an actual custom scroller needs getter/setter integration and synchronized updates. ScrollSmoother has its own wrapper/transform contract. Preserve anchors, keyboard scroll, history/restoration, focus and reduced-motion behavior as project acceptance criteria. Source: [official proxy reference](https://gsap.com/docs/v3/Plugins/ScrollTrigger/static.scrollerProxy()/), [official ScrollSmoother reference](https://gsap.com/docs/v3/Plugins/ScrollSmoother/); acceptance criteria derive from current MOT rules. Placement: advanced scroll subsection.

## Do not import without correction

- `gsap-scrolltrigger/SKILL.md:61,279` reverses refresh priority direction. Official reference explicitly places priority 1 before 0. Preserve higher-before-lower when mentioning the API.
- `gsap-scrolltrigger/SKILL.md:235` horizontal example is unusable as written: `Max.max` is undefined, a pixel difference is assigned to `xPercent`, clamping to a nonnegative value removes intended leftward overflow, and its ScrollTrigger omits the scrub advertised by preceding instructions. Rebuild an independently verified example; do not copy it.
- `gsap-react/SKILL.md:43` and `.github/instructions/react.instructions.md` claim context-safe callbacks become no-ops after unmount. Official React documentation describes recording GSAP resources and still requires explicit listener removal; do not treat this wrapper as stale-callback cancellation.
- Component-local cleanup should not use the vendor's `ScrollTrigger.getAll().forEach(kill)` recipe; it can destroy unrelated live owners. Reserve global cleanup for genuine application-level disposal.
- `gsap-performance/SKILL.md:58-59` claims pin promotion and reduced scroll work from numeric scrub. These are not measured guarantees. Numeric scrub changes catch-up behavior; pinning changes layout/positioning. MOT-009/019/020 and PERF/OPT evidence are stronger. Also do not import blanket permanent `will-change` on every animated element.
- Vendor source prescribes GSAP as the default for unspecified animation tasks (`README`, core, React, frameworks, index). Reject this recommendation policy; MOT-015 and existing-native-first decision scope win.
- Vendor core reduced-motion recipe changes duration without ensuring final destination/operability and can still jump spatial state. Current MOT-006/MOT-021 require the meaningful fallback, including disabling nonessential pins/parallax.
- Vendor core frames `immediateRender` as avoiding FOUC; it applies only after execution. Preserve baseline content and failure recovery.
- `gsap-utils/SKILL.md:194-200` documents `unitize(value, unit)` and examples as though it appends units directly. Official API takes a **function**, returns a wrapping function, strips input units and applies the result unit. [Official unitize](https://gsap.com/docs/v3/GSAP/UtilityMethods/unitize()/).
- `gsap-utils/SKILL.md:130-132` says shuffle returns a new array. It shuffles and returns the same input array; copy first where mutation is inappropriate. [Official shuffle](https://gsap.com/docs/v3/GSAP/UtilityMethods/shuffle()/).
- `gsap-plugins/SKILL.md:94-96` misdescribes Flip: `nested` prevents compounded nested transforms through extra calculations; scale is not the default resizing strategy (width/height are default), and `simple` skips transform accommodations. [Official Flip](https://gsap.com/docs/v3/Plugins/Flip/). Do not copy this options table.
- Vendor SplitText option table suggests `aria: none` plus an accessible duplicate. That leaves the visual content's semantics exposed too; official duplicated-content strategy uses hidden visual splitting. Avoid a blanket duplication recipe altogether; verify reading order and no duplicate keyboard targets.
- Do not copy static `LOW risk` as a security assessment or vendor audit badges as verification evidence. No entire vendor code samples or logo assets are needed.
