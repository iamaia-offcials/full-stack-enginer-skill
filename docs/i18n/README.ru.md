# Full Stack Engineering Skill

[English](../../README.md) · [Русский](README.ru.md) · [Español](README.es.md) · [العربية](README.ar.md) · [Türkçe](README.tr.md) · [简体中文](README.zh-CN.md)

**Переносимый инженерный стандарт для ИИ-ассистентов: правила принятия решений, объяснения и примеры для планирования, разработки и сопровождения программного продукта.**

Основной навык `unified-development-standard` работает самостоятельно. Он помогает понять продукт, выбрать подходящий стек и реализовать запрошенную часть с необходимыми проверками. Исправление текста не должно превращаться в полный аудит.

## Что входит

- Целевая картина продукта, бизнес-правила, первый релиз/MVP, выбор стека и оценка сложности.
- Архитектура, владение логикой, backend, API и интеграции.
- Валидация, авторизация, секреты и обеспечение бизнес-инвариантов на доверенной стороне.
- Ограничения БД, транзакции, индексы, миграции и восстановление.
- Frontend, поддерживаемая структура стилей, доступность и адаптивность без навязывания бренда.
- Техническое SEO и планирование аналитики/пикселей до подключения сервисов.
- Git, экономный CI/CD, контейнеры при необходимости, выпуск и эксплуатация.
- Живая документация: актуальное описание функции обновляется на месте; планы и история различаются.

Принцип: **условие → решение → причина → пример → проверка**. Проверка формата email, параметризованный SQL, безопасный вывод и авторизация решают разные задачи; чёрный список символов их не заменяет.

## Контекст и язык

Все устанавливаемые инструкции написаны **на английском**. ИИ должен отвечать на вашем языке. Входной файл направляет к нужным разделам, а не требует читать все 28 справочников. По умолчанию устанавливается один самодостаточный core; 18 специализированных профилей необязательны. Переводы README не входят в устанавливаемый скилл.

Английский может требовать меньше токенов у некоторых токенизаторов, но экономия зависит от текста и модели. Выборочное чтение и устранение повторов тоже важны. В [результатах проверки](../REVIEW.md) замеры текста и токенов отделены от реального поведения агента.

## Быстрая установка

Нужен **Python 3.10+**, без pip-зависимостей. В Windows можно использовать `py`, в Linux/macOS — `python3`. Git нужен для клонирования; альтернатива — **Code → Download ZIP** на GitHub с последующей распаковкой.

```bash
git clone https://github.com/iamaia-offcials/full-stack-enginer-skill.git
cd full-stack-enginer-skill
python tooling/install.py --agent codex --scope user
```

Установщик копирует локальные файлы. Он не скачивает зависимости, не обращается к аккаунтам и не изменяет `AGENTS.md`, `CLAUDE.md` или `GEMINI.md`.

Для установки в существующий проект:

```bash
python tooling/install.py --agent codex --repo "/path/to/my-project" --dry-run
python tooling/install.py --agent codex --repo "/path/to/my-project"
```

Пример пути Windows: `"C:/dev/my-project"`. Источник и место установки не должны пересекаться: не указывайте каталог самого набора.

## Совместимость с агентами

| Инструмент | `--agent` | В проекте | Для пользователя |
|---|---|---|---|
| Codex | `codex` | `.agents/skills/` | `~/.agents/skills/` |
| Claude Code | `claude` | `.claude/skills/` | `~/.claude/skills/` |
| Gemini CLI | `gemini` | `.gemini/skills/` | `~/.gemini/skills/` |
| Antigravity App / IDE | `antigravity` | `.agents/skills/` | `~/.gemini/config/skills/` |
| Antigravity CLI | `antigravity-cli` | `.agents/skills/` | `~/.gemini/antigravity-cli/skills/` |
| Другой совместимый агент | `generic` или `--target` | Зависит от среды | Зависит от среды |

Выберите команду для своего инструмента:

```bash
python tooling/install.py --agent claude --scope user
python tooling/install.py --agent gemini --repo "/path/to/my-project"
python tooling/install.py --agent antigravity --scope user
python tooling/install.py --target "/path/to/another-agent/skills"
```

Избегайте дублирующих копий в каталогах, которые видит один агент. Gemini также поддерживает `.agents/skills`, поэтому общая установка Codex уже может быть доступна. Проверьте список навыков, затем явно попросите применить `unified-development-standard`. При необходимости обновите список или начните новую сессию. Копирование файлов и фактическое применение моделью — разные проверки.

Пути сверены 2026-10-27 с официальной документацией: [Codex](https://learn.chatgpt.com/docs/build-skills), [Claude Code](https://code.claude.com/docs/en/skills), [Gemini CLI](https://geminicli.com/docs/cli/skills/), [Antigravity](https://antigravity.google/docs/skills). Интерфейсы могут меняться; полноценный запуск во всех платформах здесь не заявляется.

### Lovable и облачные интерфейсы

В Lovable откройте **Workspace settings → Skills → Add → Import from GitHub** и выберите [папку основного скилла](https://github.com/iamaia-offcials/full-stack-enginer-skill/tree/main/.agents/skills/unified-development-standard). По [документации Lovable](https://docs.lovable.dev/features/skills) необходимы права владельца или администратора workspace. Альтернатива — **Upload ZIP**.

Создать переносимый архив:

```bash
python tooling/package.py
```

Результат — `dist/unified-development-standard.zip`: входной файл, справочники, руководства, примеры и лицензия. Импортируйте весь пакет: одного `SKILL.md` недостаточно. Установка в Claude Code не устанавливает скилл в облачный аккаунт Claude — используйте поддерживаемый аккаунтом импорт. Установщик не управляет облачными аккаунтами.

Если агент видит файлы, но не поддерживает навыки, попросите прочитать основной `SKILL.md` и нужные связанные разделы. Без файлов или импорта инструкции передаются в чат; это не автоматическая установка. Совместимость определяется возможностями среды, а не только названием модели.

## Установка силами ИИ

Передайте запрос агенту с доступом к терминалу и файлам:

> Установи инженерный скилл из https://github.com/iamaia-offcials/full-stack-enginer-skill.git. Прочти README и установщик. Выбери каталог навыков для текущего инструмента и запрошенную область установки; если область не указана, используй текущий проект. Выполни dry-run, затем установку без изменения существующих файлов инструкций проекта и перезаписи локальных правок. Проверь установленный SKILL.md и справочники, отдельно сообщи, обнаруживает ли агент навык. Если файловая установка недоступна, используй документированный импорт или объясни конкретное ограничение.

Для облачных интерфейсов используйте GitHub/ZIP-импорт выше. Наличие чата само по себе не означает наличие Python-терминала.

## Необязательные профили

Core уже охватывает все направления. Профили нужны, если полезны отдельные специализированные процедуры. Установщик всегда добавляет зависимость core.

```bash
python tooling/install.py --list
python tooling/install.py --agent codex --scope user --skills uds-security,uds-backend
python tooling/install.py --agent codex --scope user --skills all
```

Профили: `uds-product-discovery`, `uds-requirements-planning`, `uds-architecture`, `uds-design-system`, `uds-frontend`, `uds-web-development`, `uds-technical-seo`, `uds-backend`, `uds-data`, `uds-mobile-development`, `uds-performance-optimization`, `uds-dependency-upgrades`, `uds-code-review`, `uds-testing`, `uds-security`, `uds-git-cicd`, `uds-operations`, `uds-project-audit`.

## Примеры использования

> Примени unified-development-standard. Спланируй кабинет клиентов: определи целевую картину и бизнес-правила, выдели первый релиз, оцени будущие команды сотрудников и оплату, выбери стек. Объясни, какой фундамент обоснован сейчас и что можно отложить.

> Примени unified-development-standard. Добавь email в существующую CRM. Используй текущий компонент и контракт, проверь серверную валидацию и права, обнови актуальную документацию функции и выполни относящиеся к задаче проверки.

## Обновление, восстановление и удаление

В локальной копии репозитория получите изменения и повторите установку с тем же агентом, областью и набором навыков:

```bash
git pull --ff-only
python tooling/install.py --agent codex --scope user --update --dry-run
python tooling/install.py --agent codex --scope user --update
```

Если установлены профили, при обновлении укажите тот же `--skills`. Установщик хранит хеши файлов и останавливается при локальных изменениях или добавленных файлах. Сначала сохраните и согласуйте их с новой версией. Для перехода со старой установки без манифеста сначала просмотрите файлы, затем явно выполните:

```bash
python tooling/install.py --agent codex --scope user --update --adopt-existing --dry-run
python tooling/install.py --agent codex --scope user --update --adopt-existing
```

`--adopt-existing` заменяет папки совпадающих навыков, сохраняя прежние файлы в `.uds-backups/` рядом с каталогом `skills/`. Он не обходит защиту локально изменённой управляемой установки. При обычной ошибке замены выполняется откат; после прерывания процесса или отключения питания восстанавливайте из резервной копии. Перед ручным восстановлением сохраните текущую папку, затем верните нужную копию под исходным именем навыка.

Для удаления уберите только папку выбранного установленного навыка. Удаление core нарушит работу зависящих от него профилей. Облачные навыки удаляются через настройки соответствующей среды. Не удаляйте чужие навыки.

Symlink, junction и reparse paths намеренно не поддерживаются. Если после сбоя остался `.uds-install.lock`, сначала убедитесь, что установщик не работает, затем удалите только этот lock-файл.

## Репозиторий и проверки

```text
README.md                       Основное английское описание и установка
LICENSE                         MIT
.agents/skills/
  unified-development-standard/ Core, правила, руководства, шаблоны и примеры
  uds-*/SKILL.md                 Необязательные процедуры по направлениям
docs/i18n/                      Переводы публичного README
docs/REVIEW.md                   Текущие результаты проверки и ограничения
tooling/                        Установка, упаковка, валидация и оценка
tests/                          Регрессионные тесты файловых операций и пакета
```

```bash
python tooling/validate_suite.py
python -m unittest discover -s tests -v
python tooling/package.py
```

Проверки охватывают метаданные, локальные ссылки, ID правил, установку, защиту обновления и переносимость архива. Они не доказывают правильность работы каждого агента или безопасность приложения. См. [результаты проверки](../REVIEW.md) и [руководство по оценке поведения](../../tooling/EVALUATION_GUIDE.md).

Вклад в проект: меняйте каноническое правило с сохранением ID, добавляйте полезные объяснения/примеры и воспроизводимый сценарий для изменений поведения. Документацию обновляйте на месте. Поддерживайте соответствие переводов английскому README; не создавайте языковые копии устанавливаемого скилла.
